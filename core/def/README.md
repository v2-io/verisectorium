# core/def — the term definitions

The form is the first core's (`msc/notes/17b-2026-11-07-first-core/def/README.md`), unchanged: one file per term, `<term>.md` with `-` where the term has `·`; a leading ```` ```kdl ```` block (KDL 2.0) with one `term "name" pos=noun pl="…"` node, children `subtypes`, `synonyms`, `avoid "word" "why"`, and `rel verb term="target" card="{m,n}" note="…"` (`informal=#true` when the target is a plain word, `provisional=#true` when the relation itself is a lean); then `status provisional`, or `status accepted by="…" on="…"`.

Body, in order: `# «term»` with the one-line definition under it; optional `## Intro`; `## Definition` with `### Invariants`; free sections as needed; `## Discussion`; `## Examples`; optional `## History` (how the def came to be as it is, for a later mind; revisable prose, faithful to `log.kdl`) and `## Historical Context` (where it came from: the evidence, the older methods tried, breadcrumbs into `msc/notes/`, scratch reports and other projects); `## Working Notes` (required: the inbox; what is left open, with a lean). The four record surfaces and why they are kept apart are in `src/disc-record-surfaces.md`.

**One home per invariant.** An invariant is stated once, in the def of the thing that is broken when it fails: a veritoid without a kind is a broken veritoid, so that invariant is «veritoid»'s; a stationary verisectorium with an overclaim is a broken steady state, so that one is «steady·state»'s. A def that leans on another's invariant names the term and does not restate it. A higher-level def (verisectorium most of all) states only what is true of the whole and of none of its parts.

**Standing alone.** The one-line definition, `## Definition`, `### Invariants` and `## Examples` state present truth and rest on nothing outside the def's own «references»: no path, no note number, no "see X for the derivation". Only History, Historical Context, Working Notes and, carefully, Discussion may point outside. `bin/defs check` refuses a path or a note reference inside the standalone sections.

References: `«term»` for a term with a file; `‹subtype›` for a declared subtype. Plain words defined by the outline's inline rows (truth claim, corpus, canon, ontology, acta, actum, influx, state, assembly, freestanding, content, identity, version, name, slot, inner dependency, assertion, warrant, means, attribute, standing, seat, lineage, criterion, evidence, basis, rule, acceptance, affirmation, waiver, owed, unsettled, chunk, inbox, rendering, praxis) are written plainly, without guillemets, and mean what the outline says.

`bin/defs check core` is the gate.
