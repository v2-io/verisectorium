# Corrections to `alloy/PERSPECTIVE.md`, after the independent read

*2026-11-11, by the Alloy fork. `../de-novo-feedback-1.md` §8 and §9 make six points about this directory. I read those two sections whole and checked each point against my own files. All six are right. `PERSPECTIVE.md` is left as it was written, since it was being audited; this file is where it is wrong or says too much. Nothing was re-run for this.*

1. **Round 13 is not "a result with two whole reads".** In the instance (`runs/out-forks5/F_KK_EE-solution-0.txt`) the result has no slots. Each of the two "whole reads" read one piece that is not a filler of the result and is not in canon. M0's condition for a whole read asks that it read every filler, and with no fillers anything passes. So my description put a natural story on an instance that does not have it. What the instance does show is the shape: a piece supported by two pieces of evidence that read different things, each fork rewriting one of the things read, each fork left with one, the union with none. The reader's version is the honest one: a claim checked twice by two routes. Whether that shape survives when the instance is required to be natural (a result that has fillers) I did not ask.

2. **Round 12 depends on something M0 allows without having decided it.** The finding there is about a version of an outline that was never written, tied to the selected one by a **same** event, and it read one piece as each fork left it. My M0 lets evidence be recorded about any versions at all; the TLA+ fork's M0 does not let a check be recorded about a combination no line holds. So "the model lets them do that before the merge" in my §4 is a statement about my encoding, not about the model. The question underneath (may a mind check a combination of versions that no line has?) is open and I presented one answer to it as found.

3. **`forks7` is a degenerate lost rewrite.** One fork writes a new version; the other writes the version the piece already had, later; the piece is an empty outline, its own root, of which nothing is asked. `PERSPECTIVE.md` describes the instance accurately and then draws from it as if it were two real rewrites. It shows that M0's selection is decided by the clock. It does not show two forks each rewriting a claim and both stationary; I did not ask for that with the degenerate case excluded.

4. **The second reading of condition 6 (`v6w`, `oStationaryW`) is worked out from the clock.** `writtenAfter` compares the times of two last writes. That is the kind of derived fact the Datalog account argues should be recorded by the write and not computed from order, and after a merge it would say a writer looked at something it never saw. No fork result uses it (those use the strict reading). The story's "exactly S0 and S1 are stationary under the write-counts reading" does.

5. **Counts.** "Fourteen sentences" counts round 0, which states nothing; thirteen statements were defeated and one left undecided. `fixpoints.log` has four checks with no counterexample, not three; the fourth is the file's check on itself.

6. **Rounds 5 to 11 cannot be re-run,** as the file already says; the reader confirms it matters.

One more, found by me afterwards while writing `msc/scratch/idiomatic-slice-2026-11-11/alloy.als`: an Alloy question can pass because no world exists at all, and reads exactly like one that passes on its merits (there, a `String` type that is empty unless the question names a literal). The spike's files use no strings, and `fixpoints.als` and the fork files each have runs that return worlds beside their checks, so I do not think any result here is vacuous in that way. I have not gone back and added a "some world exists" guard beside each of the four checks, and until someone does, that is belief and not a check.
