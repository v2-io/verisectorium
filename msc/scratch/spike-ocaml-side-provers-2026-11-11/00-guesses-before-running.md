# What I expect, before any of these tools has run on the model

*2026-11-11, the spike lead, written while the first install was still building. Unverified, every one. They are here so that afterwards it can be seen which the tools overturned. I have used none of these tools on this model, and what I know of Why3, Cameleer and E is from training.*

1. **Rocq.** The slice goes through in a sitting: canon as two rules, a function, and a proof that the function's answer is canon whenever it passes a check. A full proof that the function is always complete (no check needed) is more than a sitting, because it needs an argument about how many rounds suffice. The M0 story runs inside Rocq by computation. Extracted OCaml is readable and as fast as hand-written OCaml doing the same thing; the types lose the kind of a veritoid on the way out.
2. **Why3.** M0's conditions go down as logic functions and predicates much as SPARK took them, and the solvers discharge statements over bounded data quickly. Anything that needs induction (reachability, the fixed point) needs a lemma function written by hand; the solvers alone time out on it. E adds little behind Why3 that Alt-Ergo does not already do.
3. **Cameleer.** It does not build on OCaml 5.5 and needs an older compiler. Where it builds, it accepts code written like `pulled_out.ml` and refuses code written like `model.ml`. GOSPEL specifications read as comments beside the code, further from the model's sentences than a prover's definitions.
4. **E on its own.** It proves first-order consequences of the conditions when they are written as axioms (one direction of "the list is canon"; that good news does no harm for a single condition). It cannot state "the least set such that", so canon and the fixed point are out of its reach except as a set closed under the rules, which is weaker. It cannot say "no counterexample this small". The wrong shape for the model, and a useful engine behind Why3.
5. **Across them.** "Rocq and the OCaml it extracts to" comes out ahead of the others as a home, and ahead of Lean on the one risk I named (speed of the search). Why3 comes out as the nearest thing to what the Ada build did, on the OCaml side.
6. **About the model.** I do not expect any of them to find something about the model that the two kernel builds and the first spike did not. If one does, it will be about termination: every one of these tools makes a function say why it stops, and following pointers through a store is the place this model has never had to say it.
